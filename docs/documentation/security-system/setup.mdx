# Setup

The Security System is built from a few scripts working together rather than a single all-in-one prefab, so setup is about placing and wiring those scripts up correctly. Follow these steps to get a working role panel in your world.

---

1. **Import the Package:** Import the **Security System** package into your project. If you also want role grants/revokes to show on-screen alerts, import the **Notification System** package too *(optional — see [Actions & Notifications](./actions-and-notifications))*.

2. **Set Up Your Role Definitions:** Add the `SS_RolesManagement` script to a GameObject in your scene. This is where every role your world will use gets defined — names, colors, passwords, hierarchy, and so on. See [Roles](./roles) for the full field breakdown. You'll want at least one role configured before the rest of the system does anything useful.

3. **Set Up the Security System State:** Add the `SS_SecuritySystem` script to a GameObject. This is the networked script that tracks who currently holds which roles, the whitelist, and the keypad logic. In its Inspector:
   * Drag your `SS_RolesManagement` object into the **Roles** field.
   * Drag your `SS_SecuritySystemUI` object (see the next step) into the **Security System UI** field.
   * *(Optional)* Fill in a **User List URL** if you want to fetch a whitelist remotely — see [Assignment Methods](./assignment-methods).
   * *(Optional)* Assign a **Login Audio Source** if any of your roles will have a join sound.

4. **Set Up the Management Panel:** Add the `SS_SecuritySystemUI` script to the GameObject holding your panel's canvas. In its Inspector:
   * Assign **Player Card Prefab** with `playerCard.prefab` (or `playerCard2.prefab` for an alternate card layout) from the Security System's `Prefabs` folder.
   * Assign **Role Toggle Prefab** with `roleToggle.prefab`.
   * Assign **Role Card Prefab** with `roleCard.prefab`.
   * Assign **Content** and **Role Cards Content** to the containers you want the player cards and role columns built under.
   * *(Optional)* Assign a **Search Input Field** if you want the player list to be filterable by name.
   * Link the **Roles** and **Security System** fields back to the objects from steps 2–3.

5. **Let the Editor Build the Panel:** With at least one role configured, open the `SS_SecuritySystemUI` object's Inspector. Its custom editor automatically builds one player card per tracked slot and one role column per configured role — this happens at edit time, not at runtime, so the panel populates immediately without entering Play mode. Any time you add, remove, or reorder a role afterward, reopening this Inspector rebuilds the panel to match.

6. *(Optional)* **Add a Physical Keypad:** Drag the `SecurityKeypad` prefab from `Prefabs` into your scene wherever you want a password-entry point. On its `SS_SecurityKeypad` component, assign **Security System** to your scene's `SS_SecuritySystem`, and **UI** to its own keypad display component. See [The Security Keypad](./keypad) for the full settings breakdown.

7. *(Optional)* **Set Up Theming:** Add an `SS_ConfigUI` script to a GameObject to define your panel's colors, then wire it into the **Config UI** field on `SS_SecuritySystemUI`. See [UI & Theme](./ui-theme).

8. *(Optional)* **Link Notifications:** If you imported the Notification System, add an `SS_Notifications` script, assign its **Notification System** field to your `NS_NotificationSystem` object, and enable **Notifications Enabled** on `SS_SecuritySystem`.

---

:::tip
The player list is fixed at 40 tracked slots (`SS_Config.PLAYER_CAPACITY`). This is a constant, not an Inspector field — if your world's instance capacity is ever raised past 40, this value needs to be increased directly in the `SS_Config` script. See [Constants](./roles#constants-ss_config) on the Roles page.
:::

:::info
The very first player with a Security-flagged role in a fresh world can't come from the management panel, since granting a role from the panel requires the granter to already hold a Security role. Make sure at least one role reaches someone through the whitelist, the instance-owner auto-grant, or the keypad — see [Security Permission](./roles#security-permission).
:::
